# 티켓팅 서비스 Backend Kubernetes 로컬 환경 구축 가이드

## 📋 개요

이 가이드는 티켓팅 서비스 백엔드(main, admin, queue 서비스)를 로컬 Kubernetes 클러스터에 배포하는 과정을 다룹니다.

**배포 흐름:**

```
Docker 이미지 빌드 → Registry 업로드 → Secret 생성 → 
DB/Redis 배포 → 애플리케이션 배포 → Service 생성 → 
Ingress 설정 → 로컬 접근 설정
```

**최종 결과:** `https://local.api.ddcn41.com:포트`로 로컬에서 HTTPS 접근 가능

---

## 🔧 사전 요구사항

- Kubernetes 클러스터 (Kubespray로 구축된 로컬 클러스터)
- kubectl 설정 완료
- Docker 설치
- Private Registry 접근 권한 (ECR 또는 로컬 Registry)
- Helm 3.x (Ingress Controller 설치용)
- mkcert (로컬 SSL 인증서 생성용)

## 1️⃣ 백엔드 이미지 빌드 및 업로드

### 1-1. Docker 이미지 빌드

프로젝트 루트 디렉토리에서 각 서비스별 이미지를 빌드합니다.

```bash
# 프로젝트 루트 디렉토리로 이동
cd backend-v3

# Main Service 빌드
docker build -f module-api/Dockerfile -t ddcn41/msa/main:latest .

# Admin Service 빌드
docker build -f module-api-admin/Dockerfile -t ddcn41/msa/admin:latest .

# Queue Service 빌드
docker build -f module-queue/Dockerfile -t ddcn41/msa/queue:latest .
```

> **💡 중요:** Dockerfile 내 `COPY` 명령어가 settings.gradle에 정의된 모든 모듈을 참조할 수 있도록 빌드 컨텍스트를 프로젝트 루트로 설정해야 합니다.

### 1-2. Registry에 푸시

```bash
# Registry 주소를 변수로 설정 (예시)
REGISTRY="your-registry-address:5000"  # 또는 AWS ECR 주소

# 이미지 태그 변경 및 푸시
docker tag ddcn41/msa/main:latest $REGISTRY/ddcn41/msa/main:latest
docker push $REGISTRY/ddcn41/msa/main:latest

docker tag ddcn41/msa/admin:latest $REGISTRY/ddcn41/msa/admin:latest
docker push $REGISTRY/ddcn41/msa/admin:latest

docker tag ddcn41/msa/queue:latest $REGISTRY/ddcn41/msa/queue:latest
docker push $REGISTRY/ddcn41/msa/queue:latest
```

### 1-3. Private Registry 접근을 위한 Secret 생성

Kubernetes가 Private Registry에서 이미지를 pull 하려면 인증 정보가 필요합니다.

```bash
kubectl create secret docker-registry regcred \
  --docker-server=$REGISTRY \
  --docker-username=<사용자명> \
  --docker-password=<비밀번호> \
  --docker-email=<이메일> \
  -n default
```

> **참고:** ECR을 사용하는 경우, AWS CLI를 통해 토큰을 받아 사용해야 합니다.

```bash
kubectl create secret docker-registry regcred \
  --docker-server=<AWS-계정-ID>.dkr.ecr.<리전>.amazonaws.com \
  --docker-username=AWS \
  --docker-password=$(aws ecr get-login-password --region <리전>) \
  -n default
```

## 2️⃣ Kubernetes에 application 배포 및 cluster 내부 네트워크 설정

### 2-1. 환경변수 Secret 생성

애플리케이션 설정을 환경변수로 주입하기 위해 Secret을 생성합니다.

```

# main-service.env

DB_USERNAME=ticket
DB_PASSWORD=ticketpass
REDIS_HOST=redis-service
REDIS_PORT=6379

# admin-service.env
SERVER_PORT=8080
SPRING_PROFILES_ACTIVE=local
REDIS_HOST=redis-service
REDIS_PORT=6379
BOOKING_SERVICE_URL=http://ticketing-main-service:8080
PERFORMANCE_SERVICE_URL=http://ticketing-main-service:8080
S3_SERVICE_URL=http://ticketing-main-service:8080
SEAT_SERVICE_URL=http://ticketing-main-service:8080

# queue-service.env

DB_PASSWORD=ticketpass
REDIS_HOST=redis-service

```

**Secret 생성:**

```bash
kubectl create secret generic db-env --from-env-file=db.env
kubectl create secret generic main-service-env --from-env-file=main-service.env
kubectl create secret generic admin-service-env --from-env-file=admin-service.env
kubectl create secret generic queue-service-env --from-env-file=queue-service.env
```

> **🔒 보안 참고:** 프로덕션 환경에서는 AWS Secrets Manager 또는 HashiCorp Vault를 사용하여 민감한 정보를 관리해야 합니다.

> 참고: env의 URL, REDIS_HOST 등은 이후 만들어질 service의 이름(FQDN)

### 2-2. PostgreSQL 및 Redis 배포

로컬 테스트를 위해 PostgreSQL과 Redis를 Kubernetes에 배포합니다.

**postgresql.yaml:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: postgresql
  namespace: default
  labels:
    app: postgresql
spec:
  replicas: 1
  selector:
    matchLabels:
      app: postgresql
  template:
    metadata:
      labels:
        app: postgresql
    spec:
      containers:
      - name: postgresql
        image: postgres:15-alpine
        envFrom:
        - secretRef:
            name: db-env
        ports:
        - containerPort: 5432
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
---
apiVersion: v1
kind: Service
metadata:
  name: db-service
  namespace: default
  labels:
    app: postgresql
spec:
  type: ClusterIP
  ports:
  - port: 5432
    targetPort: 5432
    protocol: TCP
  selector:
    app: postgresql
```

**redis.yaml:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
  namespace: default
  labels:
    app: redis
spec:
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
      - name: redis
        image: redis:7-alpine
        ports:
        - containerPort: 6379
        resources:
          requests:
            memory: "128Mi"
            cpu: "100m"
          limits:
            memory: "256Mi"
            cpu: "200m"
---
apiVersion: v1
kind: Service
metadata:
  name: redis-service
  namespace: default
  labels:
    app: redis
spec:
  type: ClusterIP
  ports:
  - port: 6379
    targetPort: 6379
    protocol: TCP
  selector:
    app: redis
```

**배포:**

```bash
kubectl apply -f postgresql.yaml
kubectl apply -f redis.yaml

# 배포 확인
kubectl get pods -n default
kubectl get svc -n default
```

> **⚠️ 주의:** 현재 구성은 데이터 영속성(PersistentVolume)이 없어 Pod 재시작 시 데이터가 소실됩니다. 프로덕션에서는 AWS RDS와 ElastiCache를 사용하세요.

## 3️⃣ Kubernetes Cluster 외부의 요청을 받기 위한 Ingress 설정

### 3-1. NGINX Ingress Controller 설치

Helm을 사용하여 Ingress Controller를 설치합니다.

```bash
# Ingress Controller 설치
helm upgrade --install ingress-nginx ingress-nginx \
  --repo https://kubernetes.github.io/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace

# 설치 확인
kubectl get pods -n ingress-nginx
kubectl get svc -n ingress-nginx
```

**NodePort 확인:**
```bash
kubectl get svc ingress-nginx-controller -n ingress-nginx

# 출력 예시:
# NAME                       TYPE           CLUSTER-IP     EXTERNAL-IP   PORT(S)                      AGE
# ingress-nginx-controller   LoadBalancer   10.233.8.113   <pending>     80:30262/TCP,443:32131/TCP   3d1h
```

위 예시에서 HTTP는 30262, HTTPS는 32131 포트로 외부 접근이 가능합니다.

> 만약 NodePort를 정하고 싶다면 Service를 수정하거나 helm으로 ingress controller 설치할 때 values를 설정해줄 것

> metallb 등의 온프레미스 환경 로드밸런서를 사용하면 로컬 환경에서 고정 IP를 설정할 수 있어 NodePort를 따로 사용하지 않고도 80, 443 port에 대해 설정이 가능 (NodePort는 30000-32767 port만 사용 가능)

### 3-2. 로컬 SSL 인증서 생성

mkcert를 사용하여 로컬 개발용 SSL 인증서를 생성합니다.

```bash
# mkcert 설치 (macOS)
brew install mkcert

# 로컬 CA 설치
mkcert -install

# 인증서 생성
mkcert "*.ddcn41.com" \
  "local.ddcn41.com" \
  "local.admin.ddcn41.com" \
  "local.accounts.ddcn41.com" \
  "local.api.ddcn41.com" \
  "local.pgadmin.ddcn41.com"

# 파일명 변경
mv _wildcard.ddcn41.com+5.pem local.ddcn41.com.pem
mv _wildcard.ddcn41.com+5-key.pem local.ddcn41.com-key.pem

# Kubernetes Secret 생성
kubectl create secret tls ticket-tls \
  --cert=local.ddcn41.com.pem \
  --key=local.ddcn41.com-key.pem \
  -n default
```

> **🔒 프로덕션 참고:** AWS 환경에서는 AWS Certificate Manager(ACM)을 사용하고, AWS Load Balancer Controller를 통해 자동으로 인증서를 연결합니다.

### 3-3. Ingress 리소스 생성

**ingress.yaml:**
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ticket-backend-ingress
  namespace: default
  annotations:
    # CORS 설정
    nginx.ingress.kubernetes.io/enable-cors: "true"
    nginx.ingress.kubernetes.io/cors-allow-origin: "https://local.ddcn41.com,https://local.admin.ddcn41.com,https://local.accounts.ddcn41.com"
    nginx.ingress.kubernetes.io/cors-allow-credentials: "true"
    nginx.ingress.kubernetes.io/cors-allow-methods: "GET, POST, PUT, DELETE, OPTIONS, PATCH"
    nginx.ingress.kubernetes.io/cors-allow-headers: "DNT,X-CustomHeader,Keep-Alive,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type,Authorization"
    # SSL 설정
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
    # 보안 헤더
    nginx.ingress.kubernetes.io/hsts: "true"
    nginx.ingress.kubernetes.io/hsts-max-age: "31536000"
    nginx.ingress.kubernetes.io/hsts-include-subdomains: "true"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - local.api.ddcn41.com
    - "*.ddcn41.com"
    secretName: ticket-tls
  rules:
  - host: local.api.ddcn41.com
    http:
      paths:
      - path: /v1/admin
        pathType: Prefix
        backend:
          service:
            name: ticketing-admin-service
            port:
              number: 8080
      - path: /v1/queue
        pathType: Prefix
        backend:
          service:
            name: ticketing-queue-service
            port:
              number: 8080
      - path: /v1
        pathType: Prefix
        backend:
          service:
            name: ticketing-main-service
            port:
              number: 8080
```

**배포:**
```bash
kubectl apply -f ingress.yaml

# Ingress 확인
kubectl get ingress -n default
kubectl describe ingress ticket-backend-ingress -n default
```

## 4️⃣ 로컬 접근 설정

### 4-1. hosts 파일 수정

로컬에서 도메인으로 접근하기 위해 hosts 파일을 수정합니다.
````bash
# hosts 파일 편집
sudo vi /etc/hosts

# 다음 라인 추가 (Kubernetes 노드 IP 사용)
<노드-IP> local.api.ddcn41.com

# 예시
172.25.46.10 local.api.ddcn41.com
````

> **💡 팁:** Kubernetes의 모든 노드 IP로 접근 가능합니다 (kube-proxy의 NodePort 라우팅).

### 4-2. Frontend 환경변수 설정

현재 Frontend를 Local에서 실행할 때 `.env.local` 파일에 API의 경로가 설정되어 있으므로 Frontend 프로젝트의 `.env.local` 파일을 수정합니다.
```bash
# .env.local
VITE_API_BASE=https://local.api.ddcn41.com:32131
```

> **참고:** `32131`은 앞서 확인한 HTTPS NodePort입니다. 실제 포트 번호는 환경에 따라 다를 수 있습니다.

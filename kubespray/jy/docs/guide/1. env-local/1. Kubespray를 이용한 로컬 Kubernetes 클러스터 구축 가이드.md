# Kubespray를 이용한 로컬 Kubernetes 클러스터 구축 가이드

## 📚 개념 이해

### Kubespray란?

- Ansible 플레이북 기반의 Kubernetes 클러스터 배포 자동화 도구
- Production-ready 클러스터 구성 (HA, 보안 설정 등 포함)
- 다양한 CNI(Container Network Interface), CRI(Container Runtime) 지원

### 왜 Kubespray를 사용하나?

- **재현 가능성**: 동일한 설정으로 여러 환경 구축 가능
- **검증된 베스트 프랙티스**: 프로덕션 레벨의 설정 제공
- **유연성**: 다양한 옵션 커스터마이징 가능

```bash
sudo apt update

```

### **Step 2: 모든 노드 기본 설정**

각 노드에서 다음 작업을 수행합니다:

```bash
# 1. 호스트명 설정 (각 노드마다 다르게)
sudo hostnamectl set-hostname k8s-master  # Node1
sudo hostnamectl set-hostname k8s-worker1 # Node2
sudo hostnamectl set-hostname k8s-worker3 # Node3

# 2. /etc/hosts 파일 업데이트 (모든 노드에 동일하게 적용)
sudo tee -a /etc/hosts <<EOF
192.168.1.10 k8s-master
192.168.1.11 k8s-worker1
192.168.1.12 k8s-worker2
EOF
# ⚠️ IP 주소는 실제 환경에 맞게 수정

# 3. 방화벽 비활성화 (테스트 환경)
sudo ufw disable

# 4. Swap 비활성화 (Kubernetes 요구사항)
sudo swapoff -a
sudo sed -i '/ swap / s/^/#/' /etc/fstab

# 5. 필요한 커널 모듈 로드
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

# 6. 네트워크 파라미터 설정
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system
```

**🔍 왜 이런 설정이 필요한가?**

- **Swap 비활성화**: Kubernetes는 메모리 관리의 예측 가능성을 위해 swap 사용 금지
- **커널 모듈**: 컨테이너 네트워킹에 필요한 기능 활성화
- **네트워크 파라미터**: Pod 간 통신을 위한 브리지 네트워크 설정

### **Step 3: SSH Key 기반 인증 설정**

제어 노드(Ansible을 실행할 노드)에서:

```bash
# 1. SSH 키 생성 (Enter 3번으로 패스워드 없이 생성)
ssh-keygen

# 2. 모든 노드에 공개키 복사
ssh-copy-id user@k8s-master
ssh-copy-id user@k8s-worker1
ssh-copy-id user@k8s-worker2
# ⚠️ 'user'를 실제 사용자명으로 변경

# 3. 연결 테스트
ssh user@k8s-master 'hostname'
ssh user@k8s-worker1 'hostname'
ssh user@k8s-worker2 'hostname'
```

### **Step 4: Kubespray 다운로드 및 설정**

### **Step 5: 인벤토리 파일 구성**

```bash
# inventory/mycluster/inventory.ini 파일 생성
vi inventory/mycluster/inventory.ini
```

다음 내용으로 작성:

```ini
[all]
k8s-master ansible_host=192.168.1.10 ip=192.168.1.10
k8s-worker1 ansible_host=192.168.1.11 ip=192.168.1.11
k8s-worker2 ansible_host=192.168.1.12 ip=192.168.1.12

[kube_control_plane]
k8s-master

[etcd]
k8s-master

[kube_node]
k8s-worker1
k8s-worker2

[calico_rr]

[k8s_cluster:children]
kube_control_plane
kube_node
calico_rr

[all:vars]
ansible_user=your_username
ansible_become=yes
ansible_become_method=sudo
ansible_python_interpreter=/usr/bin/python3
```

**⚠️ 수정 필요 항목:**

- IP 주소들
- `ansible_user` (실제 사용자명으로 변경)

### **Step 6: Kubespray 설정 커스터마이징**

inventory/mycluster/group_vars/k8s_cluster/k8s-cluster.yml 편집
```bash
vi inventory/mycluster/group_vars/k8s_cluster/k8s-cluster.yml


# 추천 설정

## 네트워크 플러그인 (Calico 권장)
kube_network_plugin: calico

## Service IP 대역 (기본값 사용 가능)
kube_service_addresses: 10.233.0.0/18

## Pod IP 대역
kube_pods_subnet: 10.233.64.0/18

## DNS 설정
dns_mode: coredns
enable_nodelocaldns: true

## 컨테이너 런타임 (containerd 권장)
container_manager: containerd
```

inventory/mycluster/group_vars/k8s_cluster/addons.yml 편집
```bash
vi inventory/mycluster/group_vars/k8s_cluster/addons.yml

# 추천 설정

## Helm 설치
helm_enabled: true

## kubectl top 명령어 사용할거면 true를 해야하나 prometheus 등 observability stack 사용할거니 false
metrics_server_enabled: false

## local volume provisioner 사용하려면 true, AWS 환경에서는 EBS CSI driver 쓴다고 함
local_path_provisioner_enabled: false

## 이외에도 Gateway API, nginx ingress controller, alb ingress controller(AWS Loadbalancer Controller로 이름 바뀜), cert-manager, metalLB, argoCD 등에 대한 자동 설정이 가능하므로 필요한 기능 추가

```

본인은 helm으로 관리하려고 helm을 제외한 addons 설정은 해주지 않았음

### **Step 7: 연결 테스트**

배포 전 Ansible 연결을 테스트합니다:

```bash
cd ~/kubespray

# 모든 노드 Ping 테스트
ansible all -i inventory/mycluster/inventory.ini -m ping -kK

# 각 Node에 적용한 계정의 비밀번호 2번 입력

# 예상 출력:
# k8s-master | SUCCESS => {
#     "changed": false,
#     "ping": "pong"
# }
# ... (각 노드마다)
```

---

### **Step 8: Kubernetes 클러스터 배포**

```bash
# 플레이북 실행 (약 15-30분 소요)
ansible-playbook -i inventory/mycluster/inventory.ini \
  --become --become-user=root \
  cluster.yml -kK

# 각 Node에 적용한 계정의 비밀번호 2번 입력

# 🔍 진행 상황 모니터링
# - TASK 이름과 ok/changed/failed 상태 확인
# - 에러 발생 시 로그 확인
```

**배포 단계 이해:**

1. **Preparation**: 시스템 준비, 패키지 설치
2. **Container Runtime**: containerd 설치 및 설정
3. **Kubernetes Binaries**: kubectl, kubelet, kubeadm 설치
4. **Certificates**: TLS 인증서 생성
5. **Control Plane**: Master 노드 초기화
6. **Network Plugin**: Calico 설치
7. **Worker Nodes**: Worker 노드 클러스터 조인

### **Step 9: 클러스터 검증**

Master 노드에서:

```bash
# 1. kubeconfig 설정
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# 2. 노드 상태 확인
kubectl get nodes

# 예상 출력:
# NAME          STATUS   ROLES           AGE   VERSION
# k8s-master    Ready    control-plane   5m    v1.28.6
# k8s-worker1   Ready    <none>          4m    v1.28.6
# k8s-worker2   Ready    <none>          4m    v1.28.6

# 3. 시스템 Pod 확인
kubectl get pods -n kube-system

# 4. 클러스터 정보
kubectl cluster-info

# 5. 컴포넌트 상태
kubectl get componentstatuses  # deprecated되었지만 참고용
```

### **Step 10: kubectl 자동완성 설정 (편의성)**

```bash
# Bash 자동완성
echo 'source <(kubectl completion bash)' >> ~/.bashrc
echo 'alias k=kubectl' >> ~/.bashrc
echo 'complete -o default -F __start_kubectl k' >> ~/.bashrc
source ~/.bashrc

# 이제 'k get nodes'처럼 단축 명령어 사용 가능
```

## ✅ 테스트 워크로드 배포

클러스터가 정상 작동하는지 확인:

```bash
# 1. Nginx 배포
kubectl create deployment nginx --image=nginx --replicas=3

# 2. Pod 상태 확인
kubectl get pods -o wide

# 3. 서비스 노출
kubectl expose deployment nginx --port=80 --type=NodePort

# 4. 서비스 확인
kubectl get svc nginx

# 5. 접속 테스트 (NodePort 확인 후)
curl http://k8s-worker1:<NodePort>

# 6. 정리
kubectl delete deployment nginx
kubectl delete svc nginx
```

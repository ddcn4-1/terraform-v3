### NAT Instance

NAT Instance를 사용하기 위해서는 세 가지 선행 작업이 필요

첫 번째:

- NAT Instance를 생성했으면 Private Subnet의 Route Table에 NAT Instance를 등록해주어야 함
- AWS Console -> VPC -> 라우팅 테이블
- ticket-rtb-private1-ap-northeast-2a, ticket-rtb-private2-ap-northeast-2b 두 개의 서브넷에 대해:
  - 라우팅 -> 라우팅 편집 -> 라우팅 추가 -> 왼쪽 칸의 대상 0.0.0.0/0, 오른쪽 칸의 대상 인스턴스 선택 후 ticket-nat-instance 선택 -> 변경 사항 저장

두 번째:

- IP Forward 허용 작업 필요
- AWS Console -> EC2 -> 인스턴스 -> 생성해놓은 ticket-nat-instance -> 작업 -> 네트워킹 -> 소스 / 대상 확인 변경 -> 소스/대상 확인 -> 중지 선택

세 번째

- NAT Instance에 ssh로 접속해 iptables를 설치하고 NAT 설정을 해주어야 함

```
# iptables 설치 및 구동
sudo yum install iptables-services -y
sudo systemctl enable iptables
sudo systemctl start iptables

# forwarding 설정
vi /etc/sysctl.d/custom-ip-forwarding.conf
net.ipv4.ip_forward=1
:wq

# forwarding 적용
sudo sysctl -p /etc/sysctl.d/custom-ip-forwarding.conf

# 네트워크 인터페이스 이름 확인
netstat -i

# 다음 명령어 중 eth0을 이전 단계에서 확인한 네트워크 인터페이스 이름으로 바꾸어 명령 실행 (Amazon Linux 2023의 경우 enX0 이었음)
sudo /sbin/iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
sudo /sbin/iptables -F FORWARD
sudo service iptables save
```

참조 링크 - <https://docs.aws.amazon.com/ko_kr/vpc/latest/userguide/work-with-nat-instances.html>

```bash
# 1. 호스트명 설정 (각 노드마다 다르게)
sudo hostnamectl set-hostname ticket-control-plane
sudo hostnamectl set-hostname ticket-worker-node-1
sudo hostnamectl set-hostname ticket-worker-node-2

# 2. /etc/hosts 파일 업데이트 (모든 노드에 동일하게 적용)
sudo tee -a /etc/hosts <<EOF
10.0.11.11 ticket-control-plane
10.0.11.118 ticket-worker-node-1
10.0.12.139 ticket-worker-node-2
EOF
# ⚠️ IP 주소는 실제 환경에 맞게 수정

# 3. 방화벽 비활성화 (테스트 환경)
sudo ufw disable

# 4. Swap 비활성화 (Kubernetes 요구사항)
sudo swapoff -a
sudo sed -i '/ swap / s/^/#/' /etc/fstab

# 5. 필요한 커널 모듈 로드
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

# 6. 네트워크 파라미터 설정
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system
```

# 6. ECR 구성

## 6-1. Registry Repository 생성

AWS Console -> Elastic Container Registry -> Private registry -> 리포지토리 -> 리포지토리 생성

리포지토리 이름 : ddcn41/msa/main, ddcn41/msa/admin, ddcn41/msa/queue 총 3개 생성

## 6-2. 업로드

리포지토리 선택하고 상단 푸시 명령 보기 클릭하면 docker login 및 이미지 push를 위한 명령어 보여줌

현재 CI/CD를 구축해놓지 않았으니 로컬에서 직접 빌드 및 ECR로 이미지 push

예시 명령어

```
1. Docker Login
aws ecr get-login-password --region ap-northeast-2 | docker login --username AWS --password-stdin <계정 ID>.dkr.ecr.ap-northeast-2.amazonaws.com

2. Image Build
docker build -t ddcn41/msa/admin .

3. Image tag
docker tag ddcn41/msa/admin:latest <계정 ID>.dkr.ecr.ap-northeast-2.amazonaws.com/ddcn41/msa/admin:latest

4. Image push
docker push <계정 ID>.dkr.ecr.ap-northeast-2.amazonaws.com/ddcn41/msa/admin:latest
```

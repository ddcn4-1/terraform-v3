## 2-1. AWS LoadBalancer Controller

참조 공식문서 (EKS) - <https://docs.aws.amazon.com/ko_kr/eks/latest/userguide/lbc-helm.html>
참조 공식문서 (aws lb controller) - <https://kubernetes-sigs.github.io/aws-load-balancer-controller/latest/>

### 필요 설정

AWS LoadBalancer Controller를 사용하기 위해서는 VPC, Subnet, EC2에 Tag를 달아주어야 함

원하는_cluster_name 부분은 마음대로 정하고 다 같은 이름만 넣어주면 됨

- VPC
  - kubernetes.io/cluster/원하는_cluster_name : shared
- private subnet
  - kubernetes.io/role/internal-elb : 1
  - kubernetes.io/cluster/원하는_cluster_name : shared
- public subnet
  - kubernetes.io/role/elb : 1
  - kubernetes.io/cluster/원하는_cluster_name : shared
- EC2
  - kubernetes.io/cluster/원하는_cluster_name : owned

AWS External Cloud Provider를 설치하지 않았다면 K8s의 각 worker node에 대해 다음과 같이 EC2의 ID를 등록 필요 -> AWS LB Controller가 올바른 EC2로 라우팅 하기 위해 필요

```
# worker node의 EC2 인스턴스 ID를 kubernetes node에 patch
kubectl patch node ticket-worker-node-1 -p '{"spec":{"providerID":"aws:///ap-northeast-2a/i-xxxxx"}}' 
kubectl patch node ticket-worker-node-2 -p '{"spec":{"providerID":"aws:///ap-northeast-2c/i-xxxxx"}}'
```

### 설치

```
# Helm 저장소 추가
helm repo add eks https://aws.github.io/eks-charts 
helm repo update

# 클러스터 이름을 환경변수로 설정 (예: ddcn41-cluster)
export CLUSTER_NAME="ddcn41-cluster"
export AWS_REGION="ap-northeast-2"
export VPC_ID=<ticket-vpc의 ID>

# 설치
helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=${CLUSTER_NAME} \
  --set serviceAccount.create=true \
  --set serviceAccount.name=aws-load-balancer-controller \
  --set region=${AWS_REGION} \
  --set vpcId=${VPC_ID}

# Resources 확인
helm status aws-load-balancer-controller -n kube-system --show-resources

# Pod 상태 확인
kubectl get pods -n kube-system -l app.kubernetes.io/name=aws-load-balancer-controller

# 로그 확인
kubectl logs -n kube-system -l app.kubernetes.io/name=aws-load-balancer-controller --tail=50

# 버전 확인
kubectl get deployment -n kube-system aws-load-balancer-controller -o yaml | grep image:
```

## 4-2. Secrets 가져오기

Kubernetes -> AWS Secrets Manager 연결 방법 설정을 위해 SecretStore 생성

```yaml
# secretstore.yaml
apiVersion: external-secrets.io/v1
kind: SecretStore
metadata:
  name: aws-secretsmanager
  namespace: default
spec:
  provider:
    aws:
      service: SecretsManager
      region: ap-northeast-2
    # EKS의 경우 auth 설정으로 serviceaccount 적용 필요
```

정상적으로 등록되어 연결되었는지 확인

```bash
kubeclt get secretstore

# STATUS: Vaild, Ready: True 출력 되어야 함
```

이제 무슨 값을 가져올 지 ExternalSecret 생성

값을 가져오는 방법은 여러가지인데 다음과 같이 `data`를 이용해 하나씩 정의할 수도 있고 `dataFrom`을 이용해 한꺼번에 가져올 수도 있음

하나씩 가져오는 예제:

```
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: test-endpoint
  namespace: default
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secretsmanager
    kind: SecretStore
  target:
    name: backend-need-endpoint
    creationPolicy: Owner
  data:
  - secretKey: DB_URL
    remoteRef:
      key: test/ticket/endpoint
      property: DB_URL
  - secretKey: REDIS_HOST
    remoteRef:
      key: test/ticket/endpoint
      property: REDIS_HOST
```

한꺼번에 가져오는 예제:

```
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: test-key
  namespace: default
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secretsmanager
    kind: SecretStore
  target:
    name: backend-need-key
    creationPolicy: Owner
  dataFrom:
  - extract:
      key: test/ticket/info
```

# 5. 외부 접근을 위해 Ingress 적용하여 AWS ALB 생성 및 관리

```
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ticket-ingress
  annotations:
    # ALB 설정
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: instance
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP": 80}]'
    
    # ALB tag
    alb.ingress.kubernetes.io/tags: Environment=test,Project=ticket
    
    # ALB Security Groups
    alb.ingress.kubernetes.io/security-groups: sg-08e582337ce57ec53
    
    # external-dns를 이용해 Route 53에 자동으로 ALB로 라우팅되는 A 레코드 등록
    external-dns.alpha.kubernetes.io/hostname: api.test.domain.com
spec:
  ingressClassName: alb
  rules:
    - host: api.test.domain.com
      http:
        paths:
        - path: /v1
          pathType: Prefix
          backend:
            service:
              name: ticketing-main-service
              port:
                number: 8080
        - path: /v1/admin
          pathType: Prefix
          backend:
            service:
              name: ticketing-admin-service
              port:
                number: 8080
        - path: /v1/queue
          pathType: Prefix
          backend:
            service:
              name: ticketing-queue-service
              port:
                number: 8080
```

Ingress의 어노테이션을 통해 ALB에 ACM을 등록하거나, WAF를 연동할 수도 있다.

추가로 어노테이션을 이용해 CORS 헤더 설정도 가능하다.

어노테이션 참조 - <https://kubernetes-sigs.github.io/aws-load-balancer-controller/latest/guide/ingress/annotations/>
ALB 설정 참조 - <https://docs.aws.amazon.com/elasticloadbalancing/latest/application/enable-header-modification.html>
